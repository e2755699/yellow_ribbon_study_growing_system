# CI/CD 全自動發布

目標：使用者觸發一次，CI 自行完成發布並查證目的平台的可用狀態，通知成功／失敗／無法確認；流程不依賴對話持續、人工刷新頁面或代理記得回來。

## 接手與範圍

先讀目標 repository 指引、實際 pipeline、發布腳本與最近工作紀錄。從現況判斷 CI provider、runner、目的平台、帳號／組織、環境、App／服務、trigger、權限、簽章模式及收件管道；不要把來源案例的 Codemagic、Google Cloud、個人帳號或版本政策搬到公司。

無法從現有設定取得、且會影響方案的資訊，一次集中詢問；其餘先做唯讀盤點和本機實作。使用者已有的部署授權沿用，不反覆要求登入。若確實需要帳號管理者操作，先備妥具體設定頁、權限清單、secret 名稱與接入步驟，再集中交接。不要請使用者把私鑰或 token 貼在對話。

建立／匯出本 skill 本身不授權操作公司的系統。實際使用時依該次任務與既有授權執行；只需說明或規劃就不部署。變更 CI 不包含業務資料清理、migration、切換雲端、撤銷既有憑證或公開上架。簽章到期等例行維護與日常發布自動化分開說明。

## 實作順序

1. **訂明完成條件。** 保存 commit、release ID、目的 App／環境、版本／build、查驗條件與通知對象。以 repository 文件持續記錄實作與證據，避免只留在聊天。說明將改哪些元件和資料流；按既有授權接續實作。
2. **便宜的預檢先跑。** 用 CI 的實際身分執行唯讀 API 探測，確認權限、方案／runner 可用、SDK 相容、目的資源和必要 secrets 都能被工作取得。UI 顯示已登入或存在某憑證，不等於 CI 能使用；失敗時先查回應與 job log，不反覆登入猜原因。
3. **接通建置與發布。** 安裝所有會被分析的獨立 package 依賴，保留既有品質閘門；不要為了綠燈默默關閉檢查。沿用公司的版本／build 配號政策，處理並行發布與編號碰撞。以不可變 commit／tag 追蹤輸出；tag 工作的 branch 欄位可能是預設分支，不能當成真正來源。
4. **接通事件與查驗。** 優先使用目的平台的 webhook。驗證供應商規定的簽章，事件持久化及排程成功後才 ACK；透過 app/environment/upload/deployment ID 對應 release。回呼只觸發查驗，最後以 API 核對指定 release 的可用性。沒有相應事件時，使用有截止時間的自動查詢，不要求人工刷新。
5. **接通通知與恢復。** 使用持久佇列／排程及 release 狀態，處理重複、亂序、服務重啟、遺失 webhook、job 取消及 token 失效。成功通知只能來自可用性驗證；另外保存通知待送、送出、重試及送達證據。通知故障的備援不能依赖同一枚失效 token。
6. **實際驗收再收尾。** 讀 [驗收與證據](references/acceptance.md)，先做隔離測試，再在授權目標跑真實流程。逐項列出實測／模擬／未驗，不把 happy path 成功擴張成所有分支完成。交付單一發布入口、排錯／重試方法、秘密與簽章輪替方式、變更及證據位置。

## 狀態與恢復規則

- **主動同步知識，不等使用者提醒。** CI 架構、簽章、發布入口、通知、成本假設或驗收結論變更時，同一輪更新專案既有知識庫／操作文件及其索引，按專案約定同步任務與 changelog；影響本 skill 的可重用操作指引時同步修正相關段落。讀 [架構選擇與交接](references/architecture-handoff.md) 完成交接；核對文件一致性及提交狀態後才回報完成，不以聊天說明代替文件。
- 發布結果至少區分 `ready`、`failed`、`unknown`。目的平台明確拒絕才屬發布失敗；授權錯誤、網路問題、逾時屬無法確認，另記失敗 phase／reason。CI 編譯失敗不能冒充 Apple／部署平台處理失敗。
- 序列化範圍依 App／環境或 release lane，不能用全公司共用單一 active record 草率對應回呼。上傳結果不明時先查平台，禁止無限重傳、盲目重試外部寫入或改動舊 tag。
- 以 event ID、release ID、lease、CAS／交易或 outbox 設計去重與可恢復送信。記錄結果後通知若失敗，仍須可重試通知，不能因「結果已存在」就永久漏信；供應商有 idempotency key 就沿用，不承諾無法證明的 exactly-once delivery。
- 正常事件等待不靠每分鐘輪詢取代 webhook。可用有限退避處理事件到達後的最終一致性；另外設 watchdog 截止時間。次數、lease 與 CI timeout 依實際耗時配置，排隊、取消與註冊前失敗也需有可觀測出口。
- 外部 API 重試有界：429／暫時性 5xx 可退避；401／403 回報授權問題。反覆同一阻擋且無新證據時停止重試並保留可恢復狀態。不得無期限消耗 runner 或一直要求同一份授權。
- 憑證只放供應商 secret store，最小資源權限；不輸出於 log、artifact、截圖、skill 或 Git。CI 通知服務不需要業務資料存取權。

## 平台資料

- 選擇架構、降低 CI 等待成本或交付知識庫時，讀 [架構選擇與交接](references/architecture-handoff.md)；按現有帳號與方案選型，不預設必須新增雲端平台。
- iOS／TestFlight／Codemagic：讀 [Apple 與 Codemagic 接入](references/apple-codemagic.md)，尤其簽章模式與 Apple 可用性查驗。非 Apple 專案不用讀這份。
- 驗收：所有平台都讀 [驗收與證據](references/acceptance.md)。
- 想了解來源案例已實證與未驗界線時讀 [來源案例](references/provenance.md)；這不是公司環境的既有事實。

查閱並核對當前供應商官方文件與實際 API schema；不能只憑 skill 的範例宣稱某平台必然支援。最後用簡短結果報告交付，細節放在專案文件。回答「有沒有實跑」時，先答該功能的 Yes／No，再按需要補精確範圍。
