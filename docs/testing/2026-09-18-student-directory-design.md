# 學生名冊改版：第一版與設計參考

## 本次實作

- 名稱／頭像為第一層，學校為第二層，據點與黃絲帶為輔助資訊。
- 寬螢幕三欄、平板兩欄、分割視窗單欄；另有較密集的列表檢視。
- 搜尋姓名或學校，保留據點篩選並新增全部據點。結果人數跟著條件更新。
- 整張卡片進入詳情；編輯／刪除移至更多操作選單，刪除仍需確認。
- 移除此頁的裝飾背景圖，顏色、字級、間距、圓角使用 SystemTheme；套用已選擇的主題，包含尚未雲端發布的預設主題，並支援 Light／Dark。
- 沿用現有學生載入、返回後更新、附件頭像與黃絲帶資料來源，未修改學生資料 schema 或 Firebase rules。

## 設計依據與延伸參考

1. [Nielsen Norman Group：Cards: UI-Component Definition](https://www.nngroup.com/articles/cards-component/)
   卡片能把相關資訊分組並連到詳情，但列表更容易掃讀、比較相同欄位，也能在畫面放入更多資料。因此這版保留兩種檢視；預設卡片是先供外觀比較的提案，不代表已證實比列表好用。
2. [IBM Carbon：Data table usage](https://carbondesignsystem.com/components/data-table/usage/)
   查看工具列、搜尋、篩選、列內操作和資訊密度的實際規範。若老師常需比較學校／據點，後續可改成欄位對齊的名冊表格。
3. [Mobbin](https://mobbin.com/)
   真實產品介面與操作流程的靈感庫。可搜尋 directory、contacts、CRM，觀察搜尋、人物列表和詳情切換；視覺案例不能取代自己使用者的測試。

## 如何決定下一版

請實際使用的老師各試兩種檢視，完成三件事：找出指定學生、找同一所學校的學生、進入學生資料並返回。記錄完成時間、點錯次數、是否容易找回原位置。

優先確認的設計選擇：

- 找人時主要依姓名還是照片？這決定頭像比例和預設檢視。
- 列表最常看的三個欄位是哪些？不要把詳情頁的所有欄位搬來。
- 編輯是否高頻到需要直接露出按鈕？若是，可保留編輯，僅把刪除放入更多選單。

## 驗證範圍

- 學生列表 17 項測試：5 種 iPad／分割視窗尺寸，明暗主題、有資料的卡片與列表、姓名／學校搜尋、清除搜尋、全部據點、讀取錯誤與重試、返回。
- 頭像回歸測試另 3 項。
- 實際本機瀏覽器檢查真實資料的卡片／列表與小視窗。iPad 實機尚未驗證。
- 本次僅本機預覽，未部署。
