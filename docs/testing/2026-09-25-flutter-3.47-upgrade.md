# Flutter 3.47.5 升級紀錄（2026-09-25）

分支：`upgrade/flutter-3.47`（自 master `2393d48` 開出）。Flutter 3.24.5 / Dart 3.5.4 → **Flutter 3.47.5 / Dart 3.13.4**。

## 策略

- 只調整新 SDK 強制要求或已無法編譯的部分；其他套件留在原大版本，只做同大版本內更新（`flutter pub upgrade`）。
- 不調高 `pubspec.yaml` 的 `sdk: ">=3.0.0 <4.0.0"` 下限：提高到 3.7 以上會改用 `dart format` 新風格並重排全專案。
- 不在本次替換過時 API（`withOpacity`、`MaterialState`、`WillPopScope` 等），留待全員改用新 SDK 後另開任務。

## 變更

### Dart 依賴

- 移除 pubspec 中 FlutterFlow 匯出時固定的聯邦外掛內部套件（`*_platform_interface`、`*_web`、`*_android` 等），直接依賴改用 caret 範圍；移除 `http`、`uuid` 的 `dependency_overrides`。
- `firebase_core_platform_interface` 只供測試使用，移到 `dev_dependencies`；`setupFirebaseCoreMocks` 改從 `package:firebase_core_platform_interface/test.dart` 匯入。
- 必要升級：`intl` 0.19 → 0.20.3（`flutter_localizations` 要求）、`page_transition` 2.1.0 → 2.2.2、`google_fonts` 6.1.0 → 6.3.3（舊版在新 SDK 編譯失敗）。
- 同大版本內更新：例如 `fluttertoast` 8.2.8 → 8.2.14（舊版使用已移除的 v1 embedding）、`firebase_core` 3.6 → 3.15、`cloud_firestore` 5.4 → 5.6、`firebase_auth` 5.3 → 5.6。
- Widgetbook 產生器同步更新，`main.directories.g.dart` 已重新產生；24 個展示案例與先前相同。

### 程式

- `student_profile_overview.dart`：`ExpansionTile` 外包透明 `Material`，並讓卡片依圓角裁切。新版 `ListTile` 會對「有背景色的 `DecoratedBox` 蓋住水波紋」發出 assertion；卡片外觀不變，點擊回饋改為可見。

### Android

- Gradle 7.5 → 9.3.1、AGP 7.3.0 → 9.1.0、Kotlin 1.8.10 → 2.4.0、google-services 4.3.8 → 4.5.0、Crashlytics Gradle plugin 2.9.9 → 3.0.8。
- `namespace` 改在 `app/build.gradle` 宣告，移除三個 manifest 的 `package` 屬性。
- compileSdk／targetSdk 34 → 36（`flutter.*`）；**minSdk 23 → 24**（Flutter migrator 改為 `flutter.minSdkVersion`）。
- `lintOptions` → `lint`、`buildDir` → `layout.buildDirectory`，移除 `android.enableR8` 與手動加入的 `kotlin-stdlib-jdk7`；Java／Kotlin JVM target 17。
- 保留 migrator 加入的 `android.builtInKotlin=false`、`android.newDsl=false`：`firebase_analytics`、`fluttertoast` 仍套用 Kotlin Gradle Plugin。

### iOS

- **最低版本 14.0 → 15.0**（Flutter 3.47 最低需求）：Xcode 專案、Podfile、`AppFrameworkInfo.plist`。專案原本寫成 `14.0.0`，Flutter 內建 migrator 比對不到，所以手動遷移。
- Podfile 的 Firestore 預編譯框架 tag 11.2.0 → 11.15.0，對齊 `firebase_core` 3.15.0 使用的 Firebase iOS SDK。
- 移除過期的 `ios/Podfile.lock`（鎖在 Firebase 11.2.0，會與新 podspec 衝突）；Codemagic `ios-validation` 會以 artifact 輸出重新產生的 lock 檔。
- `pubspec.yaml` 設定 `flutter: config: enable-swift-package-manager: false`。Flutter 3.47 預設啟用 SwiftPM，會與 Podfile 以 CocoaPods 引入的 Firestore 框架重複連結 Firebase。

### 其他

- `codemagic.yaml` 兩個 workflow 改用 Flutter 3.47.5。
- `tool/check_design_system.ps1` 預設 SDK 改為 3.47.5；README、CLAUDE.md、`docs/design-system.md` 同步更新。
- Flutter tool 自動在三個 `analysis_options.yaml` 加入 build／平台目錄排除。

## 尚未驗證 / 待辦

1. **iOS 原生建置**：Windows 無法建置。需執行 Codemagic `ios-validation`，確認 `pod install`、Xcode 26.6 建置成功，再下載 artifact 中的 `ios/Podfile.lock` 提交回分支。
2. **TestFlight 與 iPad 實機測試**：iOS 驗證通過後，用 `ios-app-store-upload` 出新 build 並實機測試。
3. **需要確認的產品決策**：Android 最低版本改為 7.0（API 24）、iOS 最低版本改為 15.0。
4. **Android 實機**：只驗證了 APK 建置，尚未安裝執行。
5. **Kotlin Gradle Plugin**：Flutter 警告日後版本將只支援 Built-in Kotlin；需在升級 `firebase_analytics`、`fluttertoast` 大版本時一併遷移，並移除 `android.builtInKotlin=false`。
6. **過時 API 清理**：`deprecated_member_use` 約 80 處，全員改用 3.47.5 後另開任務。
7. **大版本升級（可選）**：Firebase 系列（core 4.x、firestore 6.x 等）、`go_router` 18、`flutter_bloc` 9、`file_picker` 13、`google_fonts` 8 等，逐項評估。
8. **Dart 語言版本／格式化**：調高 SDK 下限並一次性重新格式化，需與團隊協調時間，避免合併衝突。
