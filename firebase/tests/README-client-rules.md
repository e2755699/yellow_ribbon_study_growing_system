# Direct-client roster Rules verification

From the repository root:

```powershell
./firebase/tests/run-client-rules.ps1
```

The runner regenerates the actual Dart planner trace for the current Taiwan date, then starts an isolated `demo-yellow-ribbon-roster` Firestore emulator on 8194 (hub 4494, logs 4594, websocket 9194). It refuses occupied ports and never connects to or deploys production. Flutter defaults to the SDK used by the repository design-system gate; pass `-FlutterSdk` to override. Firebase CLI and Java must already be installed. Missing test dependencies are installed from the lockfile. An existing matching installation can be supplied with `-NodeModulesPath`.

The Node suites run serially because each clears the same demo database. Running Node directly against an existing emulator requires `ROSTER_RULES_PORT=8194`; regenerate `roster-planner-traces.json` first so the redemption date is current. The trace is emitted by `ROSTER_EXPORT_TRACE=1 flutter test test/domain/roster/roster_commands_test.dart --plain-name 'export production planner traces'`. Trace replay executes every recorded client read before its writes, so missing-document authorization and transaction behavior are tested rather than hidden by mocks.

## Coverage

The date-dependent `roster-planner-traces.json` is generated by the runner and ignored by Git. Its source is the Dart planner test; regenerate it before replay instead of committing a stale daily trace.

- 30 existing attendance records in one atomic commit.
- 30 full performance records, 30 individual wallets, 30 immutable events and a receipt in one commit. Full tags, remarks and five score fields are exercised.
- One illegal row rejects all records, wallet changes, events and receipt; revoked staff, disabled client gate and cross-site teachers are denied.
- Same-wallet concurrent redemptions cannot overspend. Award events require a matching protected membership-index entry; exceptional manager corrections verify the original performance record.
- Effective profile access and incremental corrections work with 100 historical enrollment periods. Corrections require all historical sites; transfer/archive preserve their narrower affected-site scope. A forged action cannot disguise a historical date correction.
- Original migration markers remain immutable while normal summary/session updates succeed.
- Tag tests cover nonstrings, 31 items, 81 UTF-16 units, separator injection, astral characters, newlines and empty strings.
- Full profile creation and update cover all 27 regular text fields at 10,000 characters plus birthday, classifications and booleans. Missing, reused and mismatched receipts/actions/students/operation IDs and direct receipt-only attempts are denied. Legacy attachment link/rollback updates keep their separate scoped field validation.

## Validation contract

App transactions calculate grade/reward numerical relationships. Rules retain authentication, manager roles, site boundaries, immutable identities, field shapes/ranges, membership authorization, maintenance flags, per-wallet redemption bounds and immutable receipts/events. Rules intentionally do not prove each grade-to-wallet delta formula; this is the user-approved tradeoff, not complete protection against a modified authorized client falsifying a reward amount.

Profile text validation is evaluated on the existing atomic `record_operations` receipt to stay below Firestore's per-evaluation expression limit. The student write requires a new receipt whose action and result student ID match; the receipt requires that student's post-write operation ID, actor and timestamp to match before checking all text fields. Student Rules retain allowed-key, name, date, numeric and boolean checks. This adds before/after student dependent reads only to a single-student enroll/profile operation, with no additional document write. It does not add per-student dependency reads to a 30-person daily save.

Tag validation uses a non-self-overlapping 81-character separator, an exact join/split round-trip, a nonempty terminal sentinel, and a bounded regex. No valid tag of at most 80 UTF-16 units can contain that separator. The round-trip rejects injected boundaries and nonstring coercion; astral code points are replaced with two ordinary units before measuring length. This preserves empty and multiline tags while avoiding 30 repeated Rules function expansions.

Tests are emulator verification, not deployment, real-device acceptance or proof that production metadata has been backfilled. `app_config/roster.clientWritesEnabled` must remain off until the separately reviewed migration/cutover is complete.
